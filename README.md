# Практическое задание № 3. Динамические структуры

Консольный проект на C# (.NET 9), реализующий все четыре части задания:

1. стек на собственном односвязном списке и вычисление постфиксных выражений;
2. две реализации очереди и сравнительные измерения;
3. четыре прикладных примера использования динамических структур;
4. все 12 функций обработки собственного связного списка.

Дополнительно реализованы перевод инфиксной записи в постфиксную, построение бинарного дерева из префиксной записи, автоматические тесты xUnit, генерация сценариев и отчётов.

## Требования

- .NET SDK 9.0 или новее.
- Windows, Linux или macOS с поддержкой .NET 9.
- Для тестов используется xUnit; пакеты восстанавливаются из NuGet.

Проверено на .NET SDK 9.0.305, среда выполнения .NET 9.0.9.

## Сборка и запуск

Из корня репозитория:

```powershell

dotnet test DynamicStructures.sln -c Release
dotnet run --project src/DynamicStructures -c Release
```

Без аргументов открывается интерактивное меню. Основные пункты меню:

- выполнение `input.txt` для стека и обеих очередей;
- ручной ввод команд;
- вычисление постфиксных выражений и преобразование инфиксных;
- построение бинарного дерева из префиксной записи;
- интерактивные 12 операций со связным списком;
- демонстрация всех 12 операций;
- четыре прикладных примера;
- бенчмарки и генерация отчётов.

## Формат команд стека и очереди

Команды разделяются пробелами и переводом строки:

| Токен | Действие для стека | Действие для очереди |
|---|---|---|
| `1,value` | `Push(value)` | `Enqueue(value)` |
| `2` | `Pop()` | `Dequeue()` |
| `3` | `Top()` | просмотр первого |
| `4` | `IsEmpty()` | `IsEmpty()` |
| `5` | печать содержимого | печать содержимого |

Обязательный пример из задания находится в `input.txt`:

```text
3 4 1,56 1,7 1,cat 2 5 4
```

Первая команда `3` пытается посмотреть верх пустого стека. Программа не падает: выводится понятное сообщение, операция пропускается. Значение после запятой может быть словом или числом, в том числе с дополнительными запятыми внутри (`1,a,b` → значение `a,b`).

Стек печатается сверху вниз, очередь — от начала к концу. Вывод каждой операции включён в обычном режиме и исключён из измеряемого участка бенчмарка.

## Постфиксные выражения

Поддерживаются:

- бинарные операции `+`, `-`, `*`, `/`, `:`, `^`;
- унарные функции `ln`, `cos`, `sin`, `sqrt`;
- внутренний унарный минус `~` (появляется при переводе инфиксной записи).

`:` и `/` — взаимозаменяемые обозначения деления. В задании перечислен `:`, а в примере использован `/`, поэтому поддержаны оба варианта.

Есть два режима разбора:

1. **С пробелами** — числа могут быть многозначными и вещественными, например `2.5 1.5 +` или `10 20 +`. Десятичный разделитель — точка.
2. **Компактный без пробелов** — только однозначные цифры, например `78+32+/`. Это выражение читается как `7 8 + 3 2 + /` и равно `3`.

Ограничение: в компактной записи нельзя записывать многозначные и дробные числа; разделяйте их пробелами. При наличии пробелов выражение разбирается по отдельным токенам, поэтому многозначные числа записываются раздельно, например `78 32 +`. Инфиксному `2+2` соответствует постфиксное `22+` (или `2 2 +`); строка `2+2` в калькуляторе постфиксных выражений не является корректной постфиксной записью.

Функции используют радианы (`ln` — натуральный логарифм). Ошибки деления на ноль, `ln` от неположительного числа, `sqrt` от отрицательного числа, неизвестные операции, недостаток или избыток операндов возвращаются как сообщения, а не необработанные исключения.

Проверочные файлы: `data/postfix.txt` и `data/infix.txt` содержат корректные примеры, `data/postfix_invalid.txt` и `data/infix_invalid.txt` — ошибочные.

## Инфиксная запись

Поддерживаются `+`, `-`, `*`, `/`, `:`, `^`, скобки, функции `sin`, `cos`, `ln`, `sqrt`, унарный минус и унарный плюс. Приоритеты: `+ -` < `* / :` < унарный минус < `^` < функции; `^` правоассоциативна, остальные бинарные операции левоассоциативны. Функция применяется к следующему операнду/скобочной группе: `sin(0)` и `sin 0` эквивалентны.

Символ `«)»` из задания трактуется как закрывающая скобка, а не самостоятельная операция.

Не поддерживается неявное умножение (`2(3+4)`); требуется явный оператор. Некоторые примеры:

```text
2+2                 -> 2 2 +                 -> 4
(2+3)*4             -> 2 3 + 4 *             -> 20
2+3*4               -> 2 3 4 * +             -> 14
2^3^2               -> 2 3 2 ^ ^             -> 512
-2^2                -> 2 2 ^ ~               -> -4
2*-3                -> 2 3 ~ *               -> -6
sin(0)+sqrt(9)      -> 0 sin 9 sqrt +        -> 3
```

При переводе унарный минус записывается в RPN как `~`. Это внутреннее обозначение, которое понимает и калькулятор, и дерево выражения.

## Бинарное дерево из префиксной записи

`Trees/TreeBuilder.cs` восстанавливает бинарное дерево из префиксной записи. Символ `*` означает пустую связь. Алгоритм рекурсивный:

1. читает очередной символ;
2. если это `*` — возвращает `null`;
3. иначе создаёт узел и рекурсивно строит левое поддерево, затем правое;
4. после корня проверяет, что лишних символов не осталось.

Пример из задания:

```text
ABD*G***CE**FH**J**
```

Даёт дерево:

```text
A
├─ L: B
│  ├─ L: D
│  │  ├─ L: *
│  │  └─ R: G
│  │     ├─ L: *
│  │     └─ R: *
│  └─ R: *
└─ R: C
   ├─ L: E
   │  ├─ L: *
   │  └─ R: *
   └─ R: F
      ├─ L: H
      │  ├─ L: *
      │  └─ R: *
      └─ R: J
         ├─ L: *
         └─ R: *
```

Программа выводит количество узлов, листьев, высоту, обходы preorder/inorder/postorder, ASCII-схему и обратную префиксную запись. Поддерживаются пробелы между символами; пустая строка, обрыв записи, лишние символы и недопустимые символы возвращаются как понятные ошибки. Пункт меню — `20`, CLI — `--tree`.

## Связный список: 12 операций

Меню `14` открывает интерактивный раздел. Можно загрузить L и E из файлов (`data/list_L.txt`, `data/list_E.txt`), ввести списки вручную или выполнить демонстрацию. Реализованы:

1. разворот списка изменением ссылок;
2. перенос последнего элемента в начало и первого в конец;
3. количество различных элементов;
4. удаление всех вхождений значений, встречающихся более одного раза;
5. вставка независимой копии списка после первого вхождения `x`;
6. вставка в упорядоченный по неубыванию список;
7. удаление всех вхождений `E`;
8. вставка `F` перед первым вхождением `E`;
9. дописывание E к L независимыми копиями узлов;
10. разделение L по первому вхождению значения;
11. удвоение списка независимой копией;
12. обмен двух элементов по позициям.

Все операции обрабатывают пустой список, один элемент, отсутствие значения, повторяющиеся значения и границы списка. Вставка копии и удвоение не создают циклов: всегда создаются новые узлы. Для разделения списка используется семантика: первый список содержит элементы **до** первого вхождения, второй — **начиная с** него; при отсутствии значения второй список пуст. Исходный объект `source` становится первым списком.

## Очереди и бенчмарки

`ListBasedQueue<T>` использует `List<T>` и намеренно удаляет из начала через `RemoveAt(0)` — это даёт O(n) на `Dequeue`. `StandardQueue<T>` является обёрткой над `Queue<T>`. Обе реализации реализуют `IQueue<T>` и проверяются одними и теми же тестами и сценариями.

Запуск измерений:

```powershell
dotnet run --project src/DynamicStructures -c Release -- --benchmark 5
```

Программа перегенерирует `data/scenarios`, выполнит каждый сценарий 5 раз после прогрева, сохранит реальные замеры в `Reports/benchmark_all.csv`, `Reports/benchmark_stack.csv`, `Reports/benchmark_queue.csv` и сформирует `Reports/Report.md` и корневой `Report.md`. Печать в консоль в измеряемый участок не входит; чтение файла и разбор команд измеряются отдельно от выполнения операций.

Подробности: `BenchmarkMethodology.md`.

## Важные замечания

- Прикладные примеры (плейлист, история редактора, очередь печати, дерево выражения) являются вариантами по умолчанию. Их уникальность относительно других команд нужно проверять отдельно: состав группы и чужие решения неизвестны.
- Абсолютные времена бенчмарков зависят от машины, версии .NET, JIT, GC и фоновой нагрузки. Один замер не доказывает асимптотику; выводы в отчёте сопоставлены с теорией и несколькими повторами.
- В обычном режиме выводится результат каждой операции; в режиме замеров observer равен `null`, поэтому форматирование и консольный ввод-вывод не искажают измерения.
