# Алгоритмы и структуры данных

Документ описывает реализацию, инварианты, обработку ошибок и теоретические оценки сложности. Теоретические оценки отделены от эмпирических времён: последние приведены в `Report.md` и зависят от машины.

## 1. Собственный односвязный список

Класс `SinglyLinkedList<T>` (`DataStructures/SinglyLinkedList.cs`) хранит `Head`, `Tail`, `Count`. Узел `Node` содержит значение и ссылку `Next`. Стандартные `LinkedList<T>` и `List<T>` для этой структуры не используются.

Основные операции:

| Операция | Время | Память | Комментарий |
|---|---:|---:|---|
| `AddFirst` | O(1) | O(1) | обновление головы |
| `AddLast` | O(1) | O(1) | благодаря `Tail` |
| `RemoveFirst` | O(1) | O(1) | обновление головы/хвоста |
| `NodeAt(index)` | O(n) | O(1) | обход от головы |
| `InsertAt(index)` | O(n) | O(1) | поиск предыдущего узла |
| `RemoveAt(index)` | O(n) | O(1) | поиск предыдущего узла |
| `ToArray` / обход | O(n) | O(n) | копия значений |
| `HasCycle` | O(n) | O(1) | алгоритм Флойда |

Инварианты: `Count` равно числу достижимых узлов; `Tail` — последний узел; у последнего узла `Next == null`; при пустом списке `Head == Tail == null`. Метод `Adopt` используется только для разделения списка, когда две части уже готовы и нужно передать их новым объектам.

## 2. Стек на собственном связном списке

`LinkedStack<T>` хранит элементы в `SinglyLinkedList<T>`; вершина стека — голова списка.

- `Push` → `AddFirst` — O(1).
- `Pop` → `RemoveFirst` — O(1).
- `Top` → чтение `Head.Value` — O(1).
- `IsEmpty` → проверка `Count == 0` — O(1).
- `Print`/снимок → обход от вершины к основанию — O(n).

`Pop` и `Top` без предварительной проверки бросают `InvalidOperationException`; для безопасной работы предусмотрены `TryPop` и `TryTop`. Исполнитель команд использует `Try*` и выводит сообщение «стек пуст», поэтому `input.txt`, начинающийся с просмотра пустого стека, не приводит к аварийному завершению.

## 3. Очереди

### 3.1. ListBasedQueue<T>

Внутри — `List<T>`. `Enqueue` вызывает `Add`, `TryPeek` читает `_items[0]`, `TryDequeue` делает `RemoveAt(0)`.

- `Enqueue`: амортизированно O(1), но возможен O(n) при расширении массива.
- `Dequeue`: O(n), потому что после удаления первого элемента все последующие сдвигаются.
- `Peek`: O(1).
- `Snapshot`: O(n).

Именно `RemoveAt(0)` является предметом сравнения: реализация не подменяется стандартной очередью и действительно выполняет удаление из начала `List<T>`.

### 3.2. StandardQueue<T>

Обёртка над `Queue<T>`. `Enqueue`, `TryDequeue`, `TryPeek` — амортизированно O(1), память O(n). Используется как эталон для сравнения.

### 3.3. Общий интерфейс

`IQueue<T>` задаёт `Enqueue`, `TryDequeue`, `TryPeek`, `IsEmpty`, `Count`, `Snapshot`, `WriteTo`, `ImplementationName`. Благодаря этому команды, тесты и приложение печати работают с любой реализацией, а CSV-отчёт сравнивает одинаковые сценарии.

## 4. Разбор и выполнение команд

`CommandParser` читает текст построчно и разбивает на токены по пробельным символам. Допустимы `1,value`, `2`, `3`, `4`, `5`. Значение после первой запятой может содержать запятые, но не пробелы. Ошибки (команда `1` без значения, пустое значение, неизвестный токен) собираются в `CommandFile.Issues` с номером строки; корректные команды всё равно выполняются.

Сложность разбора — O(t) по числу символов/токенов, память O(t). Выполнение одной команды стоит столько же, сколько соответствующая операция структуры; суммарно для m команд O(m) для стека и O(m) для стандартной очереди; для `ListBasedQueue` с d удалениями из начала — O(m + d·n) в худшем случае.

## 5. Вычисление постфиксного выражения

Алгоритм `PostfixCalculator`:

1. Токенизация выражения.
2. Для каждого числа — `Push` в собственный `LinkedStack<double>`.
3. Для бинарной операции — два `Pop` (сначала правый, затем левый), вычисление, `Push` результата.
4. Для функции/унарного минуса — один `Pop`, вычисление, `Push`.
5. В конце стек должен содержать ровно одно значение.

### Два режима токенизации

- Если в строке есть пробельный символ, токены разделяются пробелами; числа могут быть многозначными и дробными (`2.5`, `1e3`), допускается ведущий знак.
- Если пробелов нет, включается компактный режим: каждая цифра — отдельное число, буквы образуют `ln`, `cos`, `sin`, `sqrt`, остальные символы — операции. Поэтому `78+32+/` = `7 8 + 3 2 + /` = 3, а `9sqrt` = 3.

Компактный режим **не поддерживает** многозначные и дробные числа. Это явное ограничение: для `12+` получится `1 2 +` = 3, а не 12 + ...; для дробей нужно писать `12 3 +` или `2.5 1.5 +`.

### Обработка ошибок

- недостаточно операндов (`2 +`, `sqrt` без аргумента);
- лишние значения в конце (`1 2`);
- деление на ноль (`5 0 /`, `5 0 :`);
- `sqrt` от отрицательного числа, `ln` от нуля/отрицательного;
- неизвестная операция или слово (`2 3 &`);
- некорректное число (`1.2.3`), не конечное число (`1e999`);
- пустое выражение.

Возвращается `PostfixEvaluationResult` с `Success == false` и текстом ошибки; исключения наружу не выходят. `TryValidateStructure` отдельно проверяет только арность, не вычисляя значения; это используется при переводе инфиксной записи.

### Сложность

Пусть m — число токенов. Токенизация O(m), каждая операция выполняется за O(1), каждое число/оператор обрабатывается один раз. Итого **O(m) времени**. Максимальный размер стека не превышает m (все токены — числа), поэтому дополнительная память **O(m)** в худшем случае. Для сбалансированного выражения глубина стека меньше, но оценка в худшем случае остаётся O(m).

## 6. Перевод инфиксной записи в постфиксную

Используется алгоритм сортировочной станции (shunting-yard) с собственным стеком операторов.

Приоритеты:

| Оператор | Приоритет | Ассоциативность |
|---|---:|---|
| `+`, `-` | 1 | левая |
| `*`, `/`, `:` | 2 | левая |
| унарный `-` | 3 | правая |
| `^` | 4 | правая |
| функции (`sin`, `cos`, `ln`, `sqrt`) | 5 | применяются к следующему операнду/группе |

Правила:

- число сразу попадает в выход;
- функция/унарный минус кладутся в стек;
- `(` кладётся в стек;
- `)` выталкивает операторы до `(`, затем удаляет `(`; если на вершине функция — она тоже выталкивается;
- бинарная операция выталкивает операторы с большим приоритетом, а при равном — для левоассоциативных; `^` сохраняет правоассоциативность;
- в конце стек опустошается.

Унарный минус распознаётся по позиции: в начале, после оператора, после `(` или после функции. Унарный плюс не меняет значение и не попадает в RPN. Перевод `-2^2` даёт `2 2 ^ ~`, то есть `-(2^2) = -4`; `(-2)^2` даёт `2 ~ 2 ^ = 4`; `2^-3` даёт `2 3 ~ ^`.

Проверки: пустое выражение, несбалансированные скобки, пустые скобки, два операнда подряд, оператор без левого операнда, завершение оператором/функцией/`(`, неизвестные символы и функции, неявное умножение. После построения RPN дополнительно вызывается структурная проверка арности.

Сложность: каждый токен обрабатывается один раз, каждая операция кладётся/снимается со стека не более одного раза — **O(n)** времени и **O(n)** памяти.

## 7. Двенадцать функций связного списка

Все функции находятся в `LinkedListTasks/LinkedListAlgorithms.cs` и работают со ссылками узлов. Готовые `List<T>`/`LinkedList<T>` не используются; массивы применяются только для временных флагов/снимков.

1. **Reverse** — итеративно переворачивает `Next`, обновляет `Head`/`Tail`. O(n) времени, O(1) памяти. Пустой/одиночный список не меняется.
2. **MoveLastToFront / MoveFirstToLast** — ищет предпоследний/второй узел, переставляет ссылки. O(n) времени, O(1) памяти. Для 0/1 элемента — no-op.
3. **CountDistinct** — для каждого узла проверяет, встречался ли его значение раньше; O(n²) времени, O(1) дополнительной памяти (без HashSet).
4. **RemoveNonUnique** — сначала для каждого узла считает число вхождений в исходном списке, затем удаляет все узлы с числом вхождений > 1. O(n²) времени, O(n) памяти под массивы узлов/флагов. Важно: подсчёт делается до удаления, иначе вторая копия дубликата ошибочно считалась бы уникальной.
5. **InsertCopyAfterFirst** — находит первый `x`, создаёт независимую цепочку копий всего списка и вставляет её после `x`; обновляет `Tail`/`Count` при необходимости. O(n+копия) = O(n) времени и O(n) памяти. Циклов не возникает, исходные и копии — разные узлы.
6. **InsertIntoSorted** — идёт по неубывающему списку до первого значения `> E`, вставляет перед ним; если все `<= E`, добавляет в конец. O(n), O(1). Пустой список обрабатывается добавлением.
7. **RemoveAll** — проходит список, удаляя все узлы с `E`; обновляет `Head`/`Tail`/`Count`. O(n), O(1).
8. **InsertBeforeFirst** — находит первое вхождение `E` с предыдущим узлом; вставляет `F`. O(n), O(1). При отсутствии `E` возвращает `false`, список не меняется.
9. **Concatenate** — создаёт независимые копии узлов правого списка и присоединяет их к левому. O(m) по длине правого, O(m) памяти. Правый список не меняется; при `left == right` копирование завершается до присоединения, поэтому цикл не создаётся.
10. **SplitAtFirst** — находит первое вхождение; первый список получает узлы до него, второй — начиная с него. Ссылки разрезаются, `Tail`/`Count` пересчитываются. O(n), O(1) дополнительной памяти (кроме объектов списков). Если значения нет, второй список пуст, первый не изменяется. Исходный объект становится первым списком.
11. **Duplicate** — копирует весь список независимыми узлами и присоединяет копию в конец. O(n) времени и O(n) памяти, цикла нет.
12. **SwapAt** — находит узлы и их предыдущие, переставляет ссылки с отдельной обработкой соседних узлов, головы и хвоста. O(n) из-за поиска, O(1) ссылок. Неверные индексы — `ArgumentOutOfRangeException`.

Общая особенность: при вставке/удвоении создаются новые узлы (`new Node(...)`), а не переиспользуются существующие ссылки, поэтому структура остаётся ациклической. Для проверки в тестах используется `HasCycle` (Флойд).

## 8. Прикладные примеры

- **Плейлист** (`Applications/Playlist.cs`) — собственный связный список. Вставка/удаление/перемещение в середине не требуют сдвига массива; поиск по названию O(n), перестановка после поиска — O(1) по ссылкам.
- **История редактора** (`Applications/EditorHistory.cs`) — собственный стек. Каждое изменение кладёт предыдущее состояние, Undo снимает последнее (LIFO); идеально соответствует семантике отмены.
- **Очередь печати** (`Applications/PrintQueueSimulation.cs`) — `IQueue<PrintJob>`, по умолчанию `ListBasedQueue`. FIFO гарантирует порядок поступления; в демонстрации размеры малы, поэтому O(n) удаления не критично, а интерфейс позволяет подставить `StandardQueue`.
- **Дерево выражения** (`Applications/ExpressionTree.cs`) — собственное бинарное дерево. Листья — числа, внутренние узлы — операции/функции. Построение из RPN за O(m) с собственным стеком; обходы и вычисление O(n); дерево явно хранит структуру и позволяет получить инфиксную, префиксную и постфиксную формы.

Примеры являются вариантами по умолчанию; их уникальность относительно других команд не проверялась, поскольку состав группы и чужие решения неизвестны.

## 9. Тестирование

Тесты xUnit покрывают:

- все операции `SinglyLinkedList`, стека и обеих очередей, включая пустые структуры и один элемент;
- числа, слова, отрицательные и повторяющиеся значения;
- разбор команд и ошибки;
- корректные и некорректные постфиксные выражения, домены функций, деление на ноль;
- перевод инфиксной записи: скобки, приоритеты, ассоциативность, функции, унарный минус, ошибки;
- все 12 функций списка и особые случаи;
- приложения и дерево выражения;
- CSV/Markdown-отчёты на синтетических данных и входные файлы.

Тесты не подменяют реальные замеры: бенчмарки выполняются отдельной командой и сохраняют сырые значения.
