# Практическое применение динамических структур

В проекте реализованы четыре самостоятельных примера. Каждый можно запустить из меню (пункт 16) или командой:

```powershell
dotnet run --project src/DynamicStructures -c Release -- --applications
```

Важно: это варианты по умолчанию. Уникальность относительно решений других команд не проверялась, поскольку состав группы и чужие работы неизвестны; при необходимости сценарии можно заменить.

## 1. Список: плейлист

Класс: `Applications/Playlist.cs`, демонстрация — `RunPlaylistDemo`.

Структура: `SinglyLinkedList<Song>`.

Возможности:

- добавление песни в конец;
- удаление по названию;
- перемещение песни на заданную позицию;
- вывод порядка, количества и суммарной длительности;
- поиск позиции по названию.

Почему связный список: плейлист часто меняется в середине. В массиве вставка/удаление требует сдвига хвоста, а в связном списке после нахождения места меняются несколько ссылок. Поиск по названию всё равно O(n), зато перестановка уже найденного узла не копирует массив.

Демонстрация добавляет четыре песни, переносит первую на третью позицию и удаляет её, показывая итоговый порядок и длительность.

Сложности: добавление O(1), поиск/удаление/перемещение O(n) из-за поиска, сам перенос ссылок O(1).

## 2. Стек: история действий редактора

Класс: `Applications/EditorHistory.cs`, демонстрация — `RunEditorHistoryDemo`.

Структура: `LinkedStack<string>`.

Возможности:

- `Apply(newText)` сохраняет текущее состояние в стек и устанавливает новое;
- `Undo()` снимает последнее сохранённое состояние;
- `UndoDepth`, `Current`, `SnapshotsTopFirst`, `Clear`.

Почему стек: отмена всегда относится к последнему действию. LIFO — естественная модель истории: каждое изменение кладёт предыдущую версию, Undo снимает её. Очередь здесь дала бы отмену самых старых действий, что не соответствует ожиданиям пользователя.

Демонстрация проходит состояния `"" → "Привет" → "Привет, мир" → "Привет, мир!"`, отменяет три действия до пустой строки и показывает, что следующая отмена невозможна.

Сложности: `Apply` и `Undo` — O(1), память O(k) по числу сохранённых версий.

## 3. Очередь: задания на печать

Класс: `Applications/PrintQueueSimulation.cs`, демонстрация — `RunPrintQueueDemo`.

Структура: `IQueue<PrintJob>`, по умолчанию `ListBasedQueue<PrintJob>`; можно передать `StandardQueue<PrintJob>`.

Возможности:

- `Submit` с проверкой имени и числа страниц;
- `TryProcessNext` — обработка первого задания;
- `ProcessAll`;
- `Pending`, `PendingCount`, `IsEmpty`, `Processed`.

Почему очередь: задания должны печататься в порядке поступления (FIFO). Стек нарушил бы порядок, а список без дисциплины доступа потребовал бы ручного управления началом. Очередь инкапсулирует правило «первый пришёл — первый вышел».

Демонстрация ставит три документа, показывает очередь, печатает их по одному и выводит, что очередь пуста. Для учебного примера размеры малы, поэтому O(n) удаление в `ListBasedQueue` не мешает; интерфейс позволяет заменить реализацию без изменения сценария.

Сложности: `ListBasedQueue` — Enqueue амортизированно O(1), Dequeue O(n); `StandardQueue` — O(1) амортизированно.

## 4. Дерево: арифметическое выражение

Класс: `Applications/ExpressionTree.cs`, демонстрация — `RunExpressionTreeDemo`.

Структура: собственное бинарное дерево `ExpressionTree.Node`. Листья — числа, внутренние узлы — операции и функции.

Возможности:

- построение из постфиксной записи (`FromPostfix`) и из инфиксной (`FromInfix`, через сортировочную станцию);
- рекурсивное вычисление с проверкой деления на ноль, `ln`, `sqrt` и конечности результата;
- обходы `Inorder`, `Preorder`, `Postorder`;
- хранение нормализованной исходной RPN в `SourcePostfix`.

Почему дерево: выражение иерархично. Дерево явно представляет порядок операций, позволяет получить разные формы записи и вычислить значение обходом. Стек удобен для вычисления RPN, но не сохраняет структуру после вычисления; дерево сохраняет.

Демонстрация строит `2 3 + 4 *`, показывает инфиксную, префиксную и постфиксную формы и значение 20; затем строит `sin(0)+sqrt(9)` и получает 3.

Сложности: построение O(m) по числу токенов, вычисление/обход O(n) по числу узлов, память O(n).

## Сводка

| Пример | Структура | Ключевое свойство |
|---|---|---|
| Плейлист | связный список | локальные перестановки без сдвига массива |
| История редактора | стек | LIFO-отмена последнего действия |
| Печать | очередь | FIFO-порядок заданий |
| Выражение | дерево | иерархия операций и обходы |

Все примеры используют собственные структуры проекта (кроме документированного эталона `StandardQueue` для сравнения) и покрыты автоматическими тестами.
